# Smart Text Classifier

A text classification service for an AI Engineer internship task
(Varolline — supervisor: Shahzaib Khan). It classifies short
customer-support texts into **Complaint / Inquiry / Feedback / Other**
using TF-IDF features and a tuned Logistic Regression model, exposed via a
FastAPI API and a CLI demo.

## Dataset

`data/texts.csv` — 560 short texts, balanced across the 4 classes
(140 each). Generated reproducibly by `scripts/make_dataset.py`
(seed 42) from 100 hand-written seed sentences plus seeded template
variation (synonym swaps, openers/follow-ups, casing/punctuation changes),
then deduplicated. Full details and honest limitations in
[data/DATASET.md](data/DATASET.md) — the data is **synthetic**, written to
look like customer-support traffic.

## Model

- **Cleaning** (`src/preprocess.py`): lowercase, strip URLs / emails /
  @mentions, drop `#` from hashtags, replace numbers with `<num>`, remove
  punctuation, collapse whitespace. Applied inside the pipeline via
  `FunctionTransformer`, so the API receives raw text.
- **Features**: TF-IDF word 1–2 grams + TF-IDF `char_wb` 3–5 grams
  (`FeatureUnion`, `min_df=2`, sublinear TF).
- **Main model**: LogisticRegression tuned with `GridSearchCV`
  (`C ∈ {0.1, 0.5, 1, 5, 10}`, 5-fold stratified CV, `f1_macro` scoring).
  Best: `C=5.0` (CV f1_macro 0.9756).
- **Baseline**: MultinomialNB on the same features.
- **Split**: stratified 80/20 train/test (seed 42).

## Results (held-out test set, n=112)

| Model                          | Accuracy | F1 macro | F1 weighted |
|--------------------------------|----------|----------|-------------|
| LogisticRegression (tuned)     | 1.0000   | 1.0000   | 1.0000      |
| MultinomialNB (baseline)       | 0.9375   | 0.9375   | 0.9375      |

Per-class precision/recall/F1 and the confusion matrix are in
`artifacts/classification_report.txt` and `artifacts/confusion_matrix.png`.
Note: scores are high partly because the synthetic data has clean class
boundaries — see Limitations.

## How to run

```bash
# 1. create the dataset (reproducible, seed 42)
python scripts/make_dataset.py

# 2. train (saves model + metrics + plots to artifacts/)
python src/train.py

# 3. CLI demo
python demo.py
python demo.py "My package never arrived, I want a refund"

# 4. API
uvicorn app.main:app --reload
# GET  http://127.0.0.1:8000/health
# POST http://127.0.0.1:8000/predict   {"text": "How do I track my order?"}

# 5. tests
python -m pytest tests/ -v
```

`POST /predict` returns:

```json
{
  "text": "How do I track my order?",
  "category": "Inquiry",
  "confidence": 0.947,
  "all_scores": {"Complaint": 0.01, "Inquiry": 0.947, "Feedback": 0.02, "Other": 0.023}
}
```

## Limitations

1. **Synthetic data.** The dataset is generated, not collected from real
   users, so vocabulary and phrasing are narrower and class boundaries
   cleaner than real support traffic. The 1.0 test score is optimistic and
   would drop on genuine, noisy inbox data.
2. **No ambiguous/mixed intents.** Real messages mix classes ("great,
   another broken delivery…"), use sarcasm, or code-switch — none of this
   is represented, so the model can be overconfident on such inputs.
3. **English only, single domain.** Trained on customer-support phrasing;
   it will not generalise to other domains or languages without retraining.
4. **Bag-of-words model.** TF-IDF + LogisticRegression ignores word order
   beyond bigrams and has no notion of context; long or multi-intent
   messages are handled poorly.
5. **Single annotator logic.** Labels derive from the seed sentence's
   intended class; there is no inter-annotator agreement measurement.

## Future improvements

1. **Collect and label real data** — sample genuine support messages,
   label them with two annotators, and measure agreement; then fine-tune a
   small transformer (e.g. DistilBERT) which handles context, sarcasm and
   mixed intents far better than TF-IDF.
2. **Calibration + a reject option** — calibrate predicted probabilities
   (e.g. Platt scaling) and route low-confidence or out-of-distribution
   inputs ("Other"-like or ambiguous) to human review instead of forcing a
   label; add a `/predict` confidence threshold for this.
