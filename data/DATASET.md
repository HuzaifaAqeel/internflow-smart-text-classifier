# Dataset documentation — Smart Text Classifier

## What it is

`data/texts.csv` — 560 short customer-support style texts (one per row)
labelled into 4 classes, 140 examples per class (balanced):

| label     | count |
|-----------|-------|
| Complaint | 140   |
| Inquiry   | 140   |
| Feedback  | 140   |
| Other     | 140   |

Format: `text,label`. UTF-8, quoted with the csv module, no missing values,
no exact (case-insensitive) duplicates.

## How it was created (reproducible)

Generated by `scripts/make_dataset.py` with a fixed seed (`SEED = 42`,
`random.seed(42)`), so re-running produces a byte-identical file.

1. **Hand-written seeds (25 per class, 100 total).** Each seed is a realistic
   short customer-support sentence written by hand, e.g.
   *"My order arrived damaged and the box was completely crushed"*
   → `Complaint`. `{n}` placeholders in seeds are filled with realistic
   order/product/location details (`#48213`, `size M`, `Karachi`, …).
2. **Seeded template variation.** Each seed is expanded ~5–6× by applying,
   with fixed probabilities:
   - synonym swaps (e.g. *damaged→broken*, *great→excellent*)
   - clause reordering ("x, and y" → "y, x")
   - casual rewrites: greeting openers ("Hi, …"), short follow-up clauses
     ("Please look into this as soon as possible.")
   - punctuation/casing changes (trailing "?", "!", "Thanks", occasional
     ALL CAPS — mirroring how real users type)
3. **Deduplication.** A case-insensitive dedup pass guarantees zero exact
   duplicates in the file.

## Class definitions

- **Complaint** — the user reports a problem, failure or bad experience and
  (implicitly or explicitly) wants it fixed: damaged/lost/wrong items, double
  billing, rude service, refunds pending.
- **Inquiry** — the user asks a question and wants information before/after
  purchase: delivery times, returns policy, stock, compatibility, pricing.
- **Feedback** — the user volunteers an opinion about the product/service/
  experience, positive or neutral, with no request attached: praise, thanks,
  comments on the app.
- **Other** — everything else: greetings, partnership/media requests, account
  housekeeping, off-topic chatter, typo reports.

## Honest limitations of this dataset

- **Synthetic, not collected.** No real users were involved; phrasing comes
  from the seed/variation process above, so vocabulary is narrower than
  genuine support traffic and the class boundaries are cleaner than in the
  wild (this inflates measured accuracy).
- **Single annotator logic.** Labels come from the seed's intended class, so
  there is no inter-annotator agreement measurement.
- **English only, one domain.** Customer-support phrasing; it will not
  generalise to other domains (medical, legal, …) without retraining.
- **No adversarial/ambiguous cases.** Real inboxes contain sarcasm, mixed
  intents ("great, another broken delivery…"), and code-switching — none of
  which are represented here.
